## Context

Batch 3 of [`../features/standard-traits.md`](../features/standard-traits.md) delivers the first types of `physics` and the object collision of `traits`. The rules are fixed: `physics` depends on `core` only and provides the axis-aligned box, the overlap test, a shape-query contract (implemented by `tilemap`) and a uniform-grid broad phase over plain data, with no ECS, tile map or platform type (`REQ-PHYS-001`, ADR-0021, ADR-0028); the canonical names are `Box`, `BroadPhase` and `ShapeQuery` (ADR-0037), and `ShapeQuery` is a hot path that allocates nothing per query (`interfaces.md`); `Collidable` holds a box (width, height and an offset of its center from the position, default `(0, 0)`, meters, ADR-0034), a layer, a mask and a trigger flag; the `Collision` system runs at slot 4000, uses a grid whose cell size is configured per world, default 2 m; a pair collides only if each mask includes the other's layer; object versus object is detection only; trigger enter and exit events are delivered synchronously after the system, as listeners with primitive arguments `(long objectA, long objectB)`, `objectA < objectB`, following ADR-0018; no swept detection (ADR-0030, decision 6; ADR-0034; `REQ-STD-005`, `REQ-STD-010`); the iteration order is deterministic and game logic must not depend on it (ADR-0030, decision 9); the form of batches 1 and 2 for traits and systems (ADR-0080, ADR-0081).

The documents leave open where the cell size "per world" lives (`ecs` cannot know `physics`), the type, width and reset values of the layer and mask, the default of the trigger flag, where the listeners are registered (ADR-0034 says "on the world", but `ecs` cannot know a `traits` type), whether solid pairs report events too, what a removal reports, whether the current pairs can be read, the form of the box, whether touching edges overlap, whether the shape-query contract comes now, the bounds and capacity of the grid, the order of the reported events, and whether the `REQ-ECS-009` scene gets a `Collidable`.

## Decision

1. **Cell size (owner answer).** One `CollisionSystem` per world holds the cell size: its constructor `CollisionSystem(world, transformables, collidables, cellSize, excluded)` takes it in meters, positive and finite; the constructors without it use the public constant `BroadPhase.DEFAULT_CELL_SIZE`, `2.0` m. `WorldConfig` is unchanged.
2. **Layer and mask (owner answer).** Two `int` bit sets, one bit per layer, 32 layers; an object may be in several layers. A pair collides if `(maskA & layerB) != 0 && (maskB & layerA) != 0`, so a layer of `0` collides with nothing. A new or reset `Collidable` has the layer `Collidable.DEFAULT_LAYER` (`1`, bit 0), the mask `Collidable.ALL_LAYERS` (`-1`, every layer) and is not a trigger.
3. **Events (owner answer).** `CollisionListener` (`traits`), with `onEnter(long objectA, long objectB)` and `onExit(long objectA, long objectB)`, default no-op methods like `ObjectListener`, `objectA < objectB`, is registered on the `CollisionSystem` (`addListener`, `removeListener`), the only place that knows the pairs: this is how this batch applies "registered on the world" of ADR-0034, whose `World` cannot name a `traits` type. Every accepted pair reports its enter and exit, trigger or not: object versus object is detection only (ADR-0030). When an object of an overlapping pair leaves the query (removed, its `Collidable` or `Transformable` removed, an excluded trait added), the pair reports an exit at the first step of the system after the flush that applied the change; a removed object's ID is stale during the call. The pairs of the last step are readable: `getPairCount()`, `getObjectA(pair)`, `getObjectB(pair)`; during the delivery of a step's events they are already the pairs of that step.
4. **Physics API (owner answer).** `Box` is a final mutable value (center `x`, `y`, full `width` and `height`, meters), reused by its owner, with `set`, the bounds `getMinX` to `getMaxY`, `overlaps(Box)` and the static axis test `overlaps(minA, maxA, minB, maxB)`; its values are finite and its size positive or zero (`IllegalArgumentException`). The overlap is **strict**: `minA < maxB && minB < maxA` on both axes, so boxes that only touch by an edge or a corner do not overlap. `ShapeQuery` is declared now, `int query(Box area, Box[] results)`: it writes the solid shapes overlapping the area (strict test) into the caller's boxes, at most `results.length`, in an order depending only on the provider's content and the area, and returns their count even beyond the buffer; it allocates nothing and keeps nothing; `tilemap` implements it with the tile-collision batch, which also writes its contract suite. `BroadPhase` is an unbounded hashed uniform grid: no world bounds, cells hashed into a table sized from a capacity, every table doubling when needed (a warm-up cost), never shrinking, no allocation in steady state.
5. **Event order (owner answer).** At each step the accepted pairs are sorted by `(objectA, objectB)` ascending, in place (heapsort, no allocation); all the exits are reported first, then all the enters, each in ascending pair order; for each event, the listeners in registration order. The order depends only on the IDs and boxes, never on the query order (`REQ-DET-001`).
6. **Benchmark (owner answer).** The `REQ-ECS-009` scene keeps 1,000 objects × 4 traits, so its reference stays comparable; a separate collision scene (`CollisionBenchmarkWorld`: squares of 0.5 m with `Transformable`, `Movable` and `Collidable`, bouncing in an area of 4 m² per object, the capture, `Movement`, a bounce at 3500 and `Collision`) is measured with `StepHarness` at 1,000 and 10,000 objects by `StepBenchmarkTest` and reported in the same report, without a budget assertion (no document states one).
7. **Broad-phase algorithm.** Each box is entered in every cell its bounds cover, cell `(floor(x / cellSize), floor(y / cellSize))`, saturated to the `int` range; only boxes sharing a cell are compared; a pair sharing several cells is kept only by the cell holding the lower-left corner of its overlap, so it is reported once without a set. The use is `clear()`, `add(box)` (returns the index, the bounds are copied), `findPairs()`, then `getFirst(pair) < getSecond(pair)`. The initial capacities follow the constructor's capacity: as many boxes and pairs, four cell entries per box, one or two hash buckets per entry; at most `BroadPhase.MAX_ENTRIES` (`2^30`, the limit of `WorldConfig.MAX_OBJECT_CAPACITY`) cell entries, an addition beyond it being an `IllegalStateException`. The order of the pairs depends only on the boxes and the sequence of operations since its creation.
8. **`Collidable` data.** Private fields `width`, `height`, `offsetX`, `offsetY` (`double`, meters), `layer`, `mask` (`int`), `trigger` (`boolean`), named after the parameters of ADR-0032; accessors `getWidth`, `getHeight`, `setSize(width, height)`, `getOffsetX`, `getOffsetY`, `setOffset(offsetX, offsetY)`, `getLayer`, `setLayer`, `getMask`, `setMask`, `isTrigger`, `setTrigger`, and a public `TYPE`. A size that is negative or not finite and an offset that is not finite are an `IllegalArgumentException` (a non-finite box would cover every cell); the layer and mask are not checked. A new box has a size of `0`. The box of an object is centered on `(x + offsetX, y + offsetY)`; a non-finite position makes the step fail (`IllegalArgumentException`, ADR-0017). The trigger flag changes no detection now; the tile push-out of batch 4 never blocks a trigger. No factory for `lionengine:collidable` yet (`OQ-178`).
9. **`CollisionSystem`.** `SLOT` 4000; constructors `(world, transformables, collidables)`, `(world, transformables, collidables, excluded)` and `(world, transformables, collidables, cellSize, excluded)` (`REQ-STD-011`); one query (`Transformable` and `Collidable`, none of the excluded types), exposed by `getQuery()`; `getCellSize()`. Its broad phase and its pair lists start at the trait capacity of the world and double when a step needs more. Listeners run inside the step, as part of the system: they may change trait data and record structural changes (applied at the flush), never flush, update or add a system; a listener added or removed during a delivery takes effect from the next event (copy on write, ADR-0018); an exception propagates and the world fails (ADR-0017).
10. **Bytes per instance.** Measured by `TraitMemoryTest`: 56 bytes per `Collidable` on the desktop JVM (64-bit HotSpot, compressed class pointers), written in its Javadoc and asserted as an upper bound.
11. **Allocation.** No allocation per step: `BroadPhaseAllocationTest` (1,000 random boxes per step) and `CollisionAllocationTest` (1,000 moving objects of the collision scene, with enters and exits in the measured steps) assert it over 1,000 steps with the 1 KiB tolerance, after a warm-up.

## Options considered

- Cell size: a `CollisionSystem` argument with a `physics` constant (chosen: one system per world, no `ecs` change) vs a physics configuration object (a type for one value) vs a `WorldConfig` field (`ecs` would carry a collision value).
- Layer and mask: `int` bit sets, layer 1 and every mask layer by default (chosen: a new object collides with everything, like a new `Movable` moves) vs layer and mask `0` (an unset object is invisible to collision) vs `long` bit sets (64 layers, twice the bytes for a rare need).
- Events: on the system, every pair, an exit on removal, the pairs readable (chosen) vs no exit on removal (a game counting overlaps must also listen to object removals) vs no pair list (a game keeps its own copy of the pairs).
- Box: a mutable value with a strict test (chosen: no allocation, a resting contact is not an overlap, which the push-out of batch 4 needs) vs static methods on `double`s only (eight parameters) vs an inclusive test (a box resting on another one overlaps it forever).
- Shape query: declared now (chosen: the seam is fixed with the box it uses; `interfaces.md` lists it for this batch) vs with its implementation in batch 4.
- Broad phase: a hashed unbounded grid (chosen: no world bounds to configure) vs fixed bounds clamping outer boxes to the border cells (crowded borders, a second value per world).
- Order: exits then enters, each ascending (chosen) vs one merged ascending pass (an exit and an enter of the same object interleaved) vs the query order (depends on the operation sequence).
- Benchmark: a separate collision scene (chosen) vs a fifth trait in the `REQ-ECS-009` scene (the reference value would change meaning).

## Consequences

- Positive consequences: games detect overlaps and triggers with layers, without memory churn and in the same order on every platform; the tile collision of batch 4 has its seam (`ShapeQuery`) and its box; the `REQ-ECS-009` reference stays comparable.
- Costs / constraints: one sort per step (`O(k log k)` for `k` pairs); a listener is registered on the system, not on the world; a removed object's exit comes one step after its removal, with a stale ID; a box much larger than a cell costs one entry per covered cell.
- Impact on modules and APIs: `physics` gains `Box`, `BroadPhase`, `ShapeQuery` (its `maven.javadoc.skip` removed, `REQ-CORE-003`) and, in its test JAR, `BoxListQuery`, the reference `ShapeQuery`; `traits` gains `Collidable`, `CollisionListener`, `CollisionSystem`; `examples` gains `CollisionExample` and `Arena`; the Android verification runs `PhysicsTest`.
- Impact on tests and documentation: `features/standard-traits.md`, `features/README.md`, `contracts.md`, `interfaces.md`, `api-index.md`, `engine-features.md`, `roadmap.md`, `agent-workflow.md`, `traceability.md`, `testing.md`, `android-compatibility.md`, `glossary.md`.
