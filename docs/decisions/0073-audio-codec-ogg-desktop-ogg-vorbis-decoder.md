# ADR-0073 — `audio-codec-ogg`: the desktop OGG Vorbis decoder on JOrbis

- Status: ACCEPTED
- Date: 2026-11-27
- Decision makers: project owner (JOrbis approved on 2026-11-27 for audio batch 8, with the delegation of the points the documents leave open: chained logical streams, end-of-stream handling, allocation of the decoding path, default frame limit); agent for the details under that delegation, reversible by a superseding ADR
- Related requirements: `REQ-AUDIO-002`, `REQ-AUDIO-003`, `REQ-AUDIO-006`, `REQ-AUDIO-009`, `REQ-RES-004`
- Open questions resolved: none; none opened
- Supersedes / superseded by: none; completes [ADR-0033](0033-media-defaults-module-names-filters-graphics-data-audio.md) (JOrbis named as the candidate), [ADR-0037](0037-package-tree-per-module-callbacks-and-canonical-names.md) (package `com.b3dgs.lionengine.audio.codec.ogg`), [ADR-0068](0068-long-sounds-streaming-backend-pull-and-playlists.md) (`AudioStreamDecoder`) and [ADR-0072](0072-unchecked-decoder-and-stream-failures.md) (all unchanged)

## Context

`REQ-AUDIO-002` makes OGG Vorbis the first compressed format: the platform decodes it on Android, a decoder module `audio-codec-ogg` on desktop. ADR-0033 named JOrbis, the owner approved it on 2026-11-27, and ADR-0068 fixed the interface: the decoder implements `AudioStreamDecoder`, `open` giving a `PcmSource` for the long sounds, `decode` a `PcmBuffer` within a frame limit for the short sounds and the long sounds decoded on request.

The Maven Central check of 2026-11-27 found `org.jcraft:jorbis:0.0.17`, the only version on Central (released in 2012), licensed "GNU Library General Public License, version 2 or any later version" in every source file (LGPL-2.0-or-later; the POM says "GNU Lesser General Public License"), with no dependency of its own, unmaintained since 2012. It matches the register entry ("LGPL"), and LGPL-2.0-or-later may be used under LGPL-2.1-or-later, which the register accepts.

JOrbis is a port of an early `libvorbis` (2000). The implementation found four gaps that a decoder must close itself:
- the synthesis does not trim the last frames to the granule position of the last page when the first audio page is also the last one, which is the case of every short file (0.5 s decoded to 11,264 frames instead of 11,025);
- `StreamState.init` does not reset the page sequence, so a second chained link is seen as a missing page;
- it allocates the arrays a header declares before reading them, and reads past the end of a packet: a 4 KB file with a corrupted comment header made it allocate 1.4 GB in 10 s in the corruption test, and crafted codebook or residue sizes reach gigabytes;
- it shares decoding tables between all its decoders, guarded by `synchronized` methods.

## Decision

1. **Module.** `lionengine-audio-codec-ogg` (`com.b3dgs.lionengine.audio.codec.ogg`) depends on `audio-api` and `org.jcraft:jorbis:0.0.17` only, is desktop only (`--release 25`, never in Android builds) and is the only module using `com.jcraft.jogg` and `com.jcraft.jorbis`. Its one public type is `OggVorbisDecoder`, implementing `AudioStreamDecoder`; no JOrbis type appears in its API. The game registers it explicitly for the `ogg` extension, `ShortSoundCache.setDecoder("ogg", decoder)` and `LongSoundLoader.setDecoder("ogg", decoder)` (ADR-0020); one instance serves both.
2. **Accepted streams.** An OGG stream whose first logical stream is Vorbis I, mono or stereo, any positive rate. `open` reads and checks the three header packets before any sample. Refused with an `AudioDecodingException`: data that is not OGG, a first logical stream that is not Vorbis (Opus, FLAC, Theora...), more than two channels, logical streams multiplexed together (a page of another serial number inside a link), a page whose capture pattern or checksum fails, a missing page, an audio packet that does not decode, and an unchecked exception of JOrbis on corrupted data (wrapped, cause kept). Strict like the WAV decoder: a hole is refused, not skipped as `libvorbisfile` does.
3. **Chained logical streams.** Links following one another (files concatenated) are decoded as one sound when each has the format of the first; a link of another rate or channel count is refused when it is reached, after the frames of the links before it, since a `PcmSource` has one format. Each new link allocates its Vorbis state once.
4. **End of stream.** A link ends with its end-of-stream page. Its last frames are trimmed to the granule position of its last packet, as `libvorbisfile` does, so the sound has the length the encoder gave it. After the last link, the stream must end: data that does not start a new link is refused, a page cut short is refused as truncated, and a stream ending before the end-of-stream page of its link is refused as truncated (`decode` refuses the sound; a source gives the frames decoded before, then refuses). No leading trim: a link whose first granule position implies dropped leading samples (a cut from a live stream) is decoded from its first block. After a failure a source has ended and returns `0`.
5. **Samples.** Each decoded value is scaled by 32,768, rounded to the nearest integer and clipped to 16 bits, as `libvorbisfile` does: on 43 files of every `libvorbis` and FFmpeg encoder setting (quality -1 to 10, 8 to 192 kHz, mono and stereo) the length is exact and every sample within one step of `libvorbisfile`.
6. **Header bounds** (`VorbisHeaders`, checked before JOrbis reads a header), close to `libvorbis`, as ADR-0054 asks of image decoders: the vendor and comment lengths of the comment header fit its packet; block sizes from 64 to 8,192; a codebook whose entries and dimensions need more than 24 bits together is refused (the `libvorbis` check); codebooks of more than **1,048,576 entries** or **1,048,576 values** (entries × dimensions) in total are refused, 16 times the largest setup of the `libvorbis` encoder (6,561 entries in a book, about 63,000 values); floors and residues name existing codebooks; a floor 1 has at most 63 points; the classifications of a residue fit its codebook (the `libvorbis` check); a residue range stays within the residue vector of a long block (half the block, times the channels for a residue of type 2), which JOrbis does not clamp. The mappings and modes, which allocate little, keep the checks of JOrbis. In the corruption test, the largest allocation of a corrupted 4 KB file falls from 1.4 GB to 4 MB.
7. **Frame limit.** `DEFAULT_MAX_FRAMES` = 1,920,000, the limit of `WavDecoder` (10 s at 192 kHz). An OGG header does not give the length, so `decode` decodes into blocks of `BLOCK_FRAMES` = 16,384 frames, each allocated only within the limit, refuses the sound as soon as one frame more decodes, and copies the blocks into the buffer: it never allocates samples past the limit, and holds at most twice the samples of the sound at once. Streaming has no limit (ADR-0068).
8. **Allocation of the decoding path.** `open` allocates the JOrbis state (page and packet buffers, codebooks, windows); the first packets size the synthesis buffers. Then reading a source allocates nothing: measured at 0 bytes over four seconds read directly and through the bounded buffer of a streamed long sound. A new chained link allocates its state once; a looping long sound reopens its resource and allocates a new source per pass (ADR-0069).
9. **Threads.** The decoder holds only its limit and is thread-safe; each source is independent and read by one thread at a time (ADR-0068). JOrbis guards its shared tables with its own locks, so sources decode correctly on several threads at once, but the decoding of their packets is serialized across the JVM.

Reported, not added: no leading trim (decision 4); holes refused rather than skipped (decision 2); packet decoding serialized by JOrbis (decision 9); JOrbis is unmaintained, so a defect found later is fixed in this module (as decision 6) or by a superseding ADR changing the library.

## Options considered

- JOrbis through its packet layer, the checks and trims in the module (chosen): pure Java on the desktop JDK, the library the owner approved, and every gap closed where the engine owns the code.
- JOrbis' `VorbisFile` class: needs a seekable file and reads the whole stream to index it, so it neither streams from a resource stream nor bounds its work.
- The `com.googlecode.soundlibs:jorbis` repackaging (0.0.17.4, 2016): an unofficial fork, not the artifact the register names.
- Two passes to know the length before allocating (`decode`): a resource stream cannot be read twice, and buffering the encoded bytes to read the last granule position trusts a value a corrupted file may set; blocks within the limit bound the memory without trusting the file.
- Leaving the header sizes to JOrbis (rejected: a small file could exhaust the memory, against ADR-0054); a full reimplementation of the `libvorbis` checks of mappings and modes (not needed: they allocate a few hundred bytes).

## Consequences

- Positive consequences: games play OGG Vorbis music streamed, looped and in playlists, and OGG effects as short sounds, on desktop, with the samples of `libvorbisfile`; a corrupted or crafted file is refused with bounded memory; the steady streaming path allocates nothing.
- Costs / constraints: a game registers the decoder itself; packet decoding of all OGG sources is serialized by JOrbis; a file needing more than the codebook budget, or a residue past its vector, is refused although the Vorbis specification allows it (no known encoder produces one).
- Impact on modules and APIs: new module `audio-codec-ogg` with `OggVorbisDecoder` (`DEFAULT_MAX_FRAMES`, `BLOCK_FRAMES`, `OggVorbisDecoder()`, `OggVorbisDecoder(maxFrames)`, `getMaxFrames`, `decode`, `open`); the package-private `OggVorbisSource`, `OggPackets`, `VorbisHeaders`, `VorbisBits`; `audio-api` unchanged; `examples` depends on the module.
- Impact on tests and documentation (including Android/DEX compatibility): `AudioDecoderContract` bound on the decoder; `OggVorbisDecoderTest` (formats and rates against `libvorbisfile`, limit, chained, multiplexed, non-Vorbis, truncated and corrupted streams, a corruption test of 200 runs), `OggVorbisSourceTest` (pieces, headers before samples, failures while streaming, arguments, threads, the allocation test), `VorbisHeadersTest` (every bound), `OggVorbisAudioTest` (short sounds, streamed, looping and decoded long sounds, a playlist track failing mid-stream, the allocation test through the bounded buffer); test files generated by FFmpeg and `libvorbis`, with their `libvorbisfile` decodings, recorded in `provenance.json`; `OggVorbisExample`; `dependencies.md` (JOrbis row), the feature page, `modules.md`, `interfaces.md`, `contracts.md`, the API index, the traceability. Android/DEX: not shipped on Android, where the platform decodes OGG Vorbis; the shared modules are unchanged.

## Validation
